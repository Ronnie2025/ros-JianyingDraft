# Mac 兼容与工程登记

## 目标环境

第一版的目标验证环境为 macOS 国内剪映 11.4.0，应用内验证结果以随交付保存的验证报告为准。每次运行读取实际安装信息；目标版本、检测到的版本和实测版本分别记录。以 `com.lemon.lvpro` 识别国内剪映，不将本机 CapCut 作为替代。

验证环境后续更新为11.4.2。11.4.2已完成外链重新关联、字幕实际修改、源视频前后拖边及保存重开冒烟验证，声音核对至原生音量参数。未执行成片导出和逐段试听。未登记的新版本仅允许对独立测试工程使用 `install DIR --compatibility-trial`，该参数不会将应用检查标成通过，也不能作为常规绕过版本验证的方式。

上游依赖为 [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft)，固定提交为 `c3318066d964744e2bfc66f75c71745fe8cea52a`。上游能力与本机适配各自验证，不能从 Windows 示例推出 Mac 全功能兼容。

## 工程与路径

- `build` 仅写独立输出目录；`install` 负责本机草稿目录与列表登记。
- 由环境探测或明确配置确定草稿根目录，不将某个用户目录写死在通用代码中。
- 每份草稿使用新 ID、目录和版本名称；列表更新保留其他工程，更新前保存可恢复备份。禁止覆盖同名旧工程或重写整个列表为单条记录。
- 工程文件、草稿入口和素材登记应由同一生成结果保持一致。需要补齐的 Mac 文件以当前适配实现为准，文件存在本身无法证明剪映已识别。
- 剪映运行时可能自行改写登记数据。安装前检查应用状态；无法避免写入竞争时停止安装并保留已生成目录，不强制结束应用或丢弃未保存修改。
- 默认素材留在原位置，依赖清单记录大小与 SHA-256。迁移通过明确路径映射重新绑定并核验身份，不根据文件名猜测。

## 能力边界

原生文字、素材裁切、基本构图和明确音量参数依照脚本支持范围使用。复杂蒙版、模糊、效果、字体和预制透明媒体需要逐项检查实际表现。输入明确要求的功能超出支持范围时记录为不支持，不偷偷删掉或换成近似效果。

导入后的工程可能由应用转成另一种保存结构。可读初始 JSON 不能视为用户当前保存状态。本版始终新建工程，不以初始生成文件覆盖应用保存结果。

## Mac 外链素材首次关联

本地文件存在、ffprobe可读取，与剪映已经取得文件访问权限是两项检查。实测可能先显示“暂无访问权限”或“Unsupported Media”，随后才出现独立的“链接媒体”对话框。不要立即判定编码格式损坏或重新渲染源文件。

在已授权的UI操作中，使用独立链接媒体窗口：选择待关联条目→链接媒体→原生文件选择器→定位依赖清单中的准确单个文件→确认。逐个处理，避免按同名猜测；检查画面恢复，再保存重开。导入整个源目录只增加素材库，无法替代既有时间线的关联。对于没有可用UI工具的环境，报告需完成原生关联的文件清单及当前验证状态。

## 版本变化

应用或依赖版本改变后，至少重新检查：工程列表可见、素材链接、完整时间线、文字编辑、源素材拖边、声音关系和保存重开。只将本次实际完成的项目记为通过，保留应用版本、依赖提交、测试工程和证据位置。

外链关联后时间线可能暂时仍显示红色占位，而预览已恢复。保存并重开后再次检查素材库、缩略图和预览，不能仅看首次占位图判断最终状态。

## 原生字幕样式联动

11.5.0 已对照验证：旧普通文本不显示字幕统一编辑开关；原生字幕材料显示“文本、排列、气泡、花字应用到全部字幕”。开启时修改一条字号会同步同批另一条，普通标题保持原字号。这里只涉及字幕编辑态，不创建ASR任务、不生成逐字识别时间、不改变输入换行或字号。

适配参考 [aoguai/pyJianYingDraft 的字幕材料实现](https://github.com/aoguai/pyJianYingDraft/blob/4a7730c9a14e91aa497e723c85b5c433a62a163c/pyJianYingDraft/text_segment.py#L599) 与同提交 SRT 分组实现，依然使用原先锁定的底层依赖。适配位于 `scripts/subtitle_material.py`，`materials.texts[].group_id` 与片段组合字段不同。
